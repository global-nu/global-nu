Parameter history

The register, as data

Every point on the parameter history page — Bari, NuFit and Valencia, from the first hint of θ₁₃ to subpercent precision — as a flat table, one row per value, free to download and cite.

Download

same rows, two formats, stable URLs

FileFormatURL
Parameter historyJSON/data/history.json
Parameter historyCSV/data/history.csv

Both files hold exactly the same rows and the same columns — CSV for a spreadsheet or a quick pandas.read_csv, JSON for a script. The URLs are stable: a regenerated release adds or corrects rows in place, it does not move the file. Regenerated by tools/make_history_data.py from site-src/data/history.yaml, the same source the parameter-history page itself is drawn from — the two can never disagree, because nothing is retyped between them.

The two value columns

what the paper printed, and our arithmetic — never merged into one

Every row carries the value twice, under names that cannot be confused:

  • value_as_published — exactly what the paper printed, in the paper's own convention and normalisation (see convention and unit, below).
  • value_our_convention — the same quantity converted to this group's convention: δm² = m₂² − m₁² > 0 and Δm² = m₃² − (m₁² + m₂²)/2.

Only the Dm2 parameter is ever converted. NuFit reports Δm²₃ℓ (Δm²₃₁ > 0 for normal ordering, Δm²₃₂ < 0 for inverted) and Valencia reports |Δm²₃₁| for both orderings — neither is our Δm², and the sign of the correction between the two is not even the same for the two groups (worked through on the parameter-history page). The conversion is performed by a single function, to_our_Dm2(rel, ordering, value) in tools/make_history.py, and nowhere else — read it there rather than re-deriving the identity from this page.

For every other parameter (dm2, sin2_th12, sin2_th13, sin2_th23, delta_pi) — and for Bari's own Dm2, which already is our convention — the two columns hold the identical number. That repetition is deliberate, not a column to optimise away: it means a downloader gets one column, value_our_convention, that is directly comparable across all six parameters and all three groups, without first having to know which parameter, in which release, needed the conversion.

Fields

13 columns, one row per (group, year, parameter, ordering) point

FieldMeaning
groupbari, nufit or valencia
yearPublication year of the release, as used on the parameter-history page
arxivarXiv identifier of the source paper
journalFull journal citation
tableThe table or equation, inside that paper, the value is transcribed from and checked against
parameterOne of dm2 (δm²), Dm2 (Δm²), sin2_th12, sin2_th13, sin2_th23, delta_pi (δ/π)
orderingno (normal), io (inverted) or any (the paper quotes one value for both, or does not split by ordering)
conventionThe release's own stated mass-splitting convention, verbatim from history.yaml
kindmeasurement (a best fit) or limit (a bound with no measured central value)
value_as_publishedThe number as printed in the paper — see "The two value columns", above
value_our_conventionThe same quantity in this group's convention — see "The two value columns", above
unitThe normalisation the value is written in, e.g. 1e-2 means the printed digits are hundredths
levelFor a limit row only: the confidence level the bound holds at (3sigma, 2sigma, 90%CL or 95%CL); empty for a measurement row

A best fit's 3σ (or 1σ, where that is all the paper gives) range is not in this export: the register publishes the headline value per point, best fit or bound, the same one plotted on the parameter-history page. The ranges remain readable there, and in history.yaml itself, alongside the source each number is checked against.
